FROZEN SCORING RULE

Field identity, typed values,
then source support.

This scoring contract is a proposal until exercised by the validator on testnet. No score is fabricated or shown here.

01Exact change tuple

A prediction is correct only when its field path and both typed values match the independently derived source delta.

+
02Two-sided evidence

Prior and current evidence must resolve to the corresponding value in that exact TED record.

+
03Valid protocol

Task ID and protocol version must match; duplicate fields, malformed evidence, and oversize responses are invalid.

score = 0.70 × tuple-F1 + 0.25 × evidence-precision + 0.05 × protocol-validity

Tuple precision penalizes invented changes. Tuple recall penalizes missed changes. The harmonic mean prevents either from hiding the other. Evidence precision is zero when a claimed tuple lacks verified evidence on either side. A protocol-invalid output receives zero protocol credit and its invalid tuples are discarded.

01Empty predictions＋

An empty response has zero recall whenever the live source pair contains a field difference, so a miner cannot earn a high score by refusing all work.

02TED returns no pair＋

Do not create a task. Missing source records, mismatched notice identifiers, timeout, or malformed API data are operational failures, not “no change” labels.

03Relative weights＋

Aggregate scores from completed live tasks over a declared window, assign failed miner requests zero for that task, normalize nonnegative values by UID, and submit only to the explicitly configured Bittensor test network. The chain applies subnet limits and consensus.
